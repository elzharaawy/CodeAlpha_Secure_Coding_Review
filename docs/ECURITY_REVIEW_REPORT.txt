VULNERABILITY #1: SQL INJECTION (CRITICAL)
═════════════════════════════════════════════════════════════════════════════

Location: /login route, line 38-40
Severity: 🔴 CRITICAL

Description:
User input is directly concatenated into SQL queries without sanitization.

Vulnerable Code:
    query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'"
    cursor.execute(query)

Attack Vector:
An attacker can input: username = "' OR '1'='1' --" to bypass authentication:
    SELECT * FROM users WHERE username='' OR '1'='1' --' AND password='...'

Impact:
- Unauthorized access to user accounts
- Disclosure of sensitive user data
- Modification/deletion of database records
- Complete database compromise

Remediation:
Use parameterized queries (prepared statements):
    
    ✅ SECURE CODE:
    cursor.execute("SELECT * FROM users WHERE username=? AND password=?", 
                   (username, password))

Best Practice: Always use parameterized queries with placeholders (?) for SQLite
or %s for MySQL to prevent SQL injection.

Vulnerable Code:

Impact:

- Session hijacking attacks possible
- CSRF token validation can be bypassed

Remediation:

    ✅ SECURE CODE:

Best Practice: Never hardcode secrets. Use environment variables or secure
secret management systems (AWS Secrets Manager, HashiCorp Vault, etc.)


VULNERABILITY #3: REFLECTED XSS (Cross-Site Scripting) (CRITICAL)
═════════════════════════════════════════════════════════════════════════════

Location: /search route, line 56
Severity: 🔴 CRITICAL

Description:
User input is directly rendered in HTML without escaping.

Vulnerable Code:
    query = request.args.get('q', '')
    return f"<h1>Search Results for: {query}</h1>"

Attack Vector:
URL: /search?q=<script>alert('XSS')</script>
Rendered as: <h1>Search Results for: <script>alert('XSS')</script></h1>

Impact:
- Session cookie theft
- Malware injection
- Credential harvesting
- Website defacement
- Phishing attacks

Remediation:

    ✅ SECURE CODE - Option 1: Use Jinja2 Auto-escaping
    from flask import escape
    
    query = request.args.get('q', '')
    return f"<h1>Search Results for: {escape(query)}</h1>"
    
    ✅ SECURE CODE - Option 2: Use Jinja2 Templates (Recommended)
    from flask import render_template
    
    @app.route('/search')
    def search():
        query = request.args.get('q', '')
        return render_template('search.html', query=query)
    
    # In search.html:
    <h1>Search Results for: {{ query }}</h1>

Best Practice: Always escape user input when rendering in HTML. Jinja2 templates
auto-escape by default when using {{ }} syntax.

    def login_required(f):
        @wraps(f)

        return decorated_function

        if int(user_id) != session.get('user_id'):

        db = get_db()
        cursor = db.cursor()
        cursor.execute("SELECT * FROM users WHERE id=?", (user_id,))
        user = cursor.fetchone()
        return f"User: {user}"

sensitive routes.


VULNERABILITY #5: UNSAFE FILE UPLOAD (CRITICAL)
═════════════════════════════════════════════════════════════════════════════

Location: /upload route, line 70-75
Severity: 🔴 CRITICAL

Description:
Files are saved with user-supplied names without validation. No file type checking.

Vulnerable Code:
    @app.route('/upload', methods=['POST'])
    def upload():
        file = request.files['file']
        file.save(os.path.join('/tmp', file.filename))
        return "File uploaded"

Attack Vectors:
1. Path traversal: filename = "../../etc/passwd"
2. Malicious executable upload: filename = "shell.php"
3. Zip bomb / denial of service

Impact:
- Remote code execution (RCE)
- Server filesystem compromise
- Denial of service attacks
- Malware distribution

Remediation:

    ✅ SECURE CODE:
    import os
    from werkzeug.utils import secure_filename
    from flask import abort
    
    ALLOWED_EXTENSIONS = {'txt', 'pdf', 'png', 'jpg', 'jpeg'}
    MAX_FILE_SIZE = 5 * 1024 * 1024  # 5MB
    UPLOAD_FOLDER = '/tmp/uploads'
    
    def allowed_file(filename):
        return '.' in filename and filename.rsplit('.', 1)[1].lower() in ALLOWED_EXTENSIONS
    
    @app.route('/upload', methods=['POST'])
    @login_required
    def upload():
        file = request.files['file']
        
        # Validate file exists
        if not file or file.filename == '':
            return "No file selected", 400
        
        # Validate file extension
        if not allowed_file(file.filename):
            return "File type not allowed", 400
        
        # Validate file size
        file.seek(0, os.SEEK_END)
        file_length = file.tell()
        if file_length > MAX_FILE_SIZE:
            return "File too large", 400
        
        # Use secure filename and generate unique name
        filename = secure_filename(file.filename)
        unique_filename = f"{user_id}_{uuid.uuid4()}_{filename}"
        
        filepath = os.path.join(UPLOAD_FOLDER, unique_filename)
        file.save(filepath)
        return "File uploaded successfully"

Best Practice: 
- Use secure_filename() for file names
- Validate file extension and MIME type
- Limit file size
- Store files outside web root
- Generate unique filenames


VULNERABILITY #6: UNSAFE DESERIALIZATION (CRITICAL)
═════════════════════════════════════════════════════════════════════════════

Location: /deserialize route, line 83-87
Severity: 🔴 CRITICAL

Description:
Unsafe deserialization of untrusted data using pickle module.

Vulnerable Code:
    @app.route('/deserialize', methods=['POST'])
    def deserialize():
        data = request.form.get('data')
        obj = pickle.loads(data)
        return str(obj)

Impact:
- Remote Code Execution (RCE)
- Complete system compromise
- Arbitrary command execution with app privileges

Remediation:

    ✅ SECURE CODE - Option 1: Use JSON instead of pickle
    import json
    
    @app.route('/deserialize', methods=['POST'])
    def deserialize():
        try:
            data = request.form.get('data')
            obj = json.loads(data)
            return str(obj)
        except json.JSONDecodeError:
            return "Invalid JSON", 400
    
    ✅ SECURE CODE - Option 2: Use restricted unpickler
    import pickle
    import io
    
    class RestrictedUnpickler(pickle.Unpickler):
        def find_class(self, module, name):
            # Whitelist safe classes only
            if module == "builtins" and name in ("list", "dict", "str"):
                return getattr(__builtins__, name)
            raise pickle.UnpicklingError(f"Forbidden: {module}.{name}")

Best Practice: Never use pickle to deserialize untrusted data. Use JSON for
serialization instead. If pickle is necessary, use RestrictedUnpickler.
