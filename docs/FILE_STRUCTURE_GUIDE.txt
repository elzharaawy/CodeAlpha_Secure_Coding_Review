FILE NAMING CONVENTIONS
═════════════════════════════════════════════════════════════════════════════════

NAMING RULES:
═════════════

1. FOLDER NAMES:
   - Use lowercase
   - Use hyphens for multiple words
   - Examples: docs, src, tests, config
   ✓ CORRECT: docs/, secure-coding-review/
   ✗ WRONG: Docs/, DOCS/, Secure Coding Review/

2. PYTHON FILES:
   - Use snake_case (lowercase with underscores)
   - Descriptive names
   - Examples: vulnerable_app.py, secure_app.py, test_auth.py
   ✓ CORRECT: test_security.py
   ✗ WRONG: TestSecurity.py, test-security.py

3. DOCUMENTATION FILES:
   - Use UPPERCASE_WITH_UNDERSCORES.txt
   - Or UPPERCASE.md for markdown
   - Examples: README.md, SECURITY_REVIEW_REPORT.txt
   ✓ CORRECT: SECURITY_REVIEW_REPORT.txt
   ✗ WRONG: security_review_report.txt, Security Review Report.txt

4. CONFIG FILES:
   - Use .env for environment variables
   - Use .gitignore for git ignore patterns
   - Use config.py or settings.py for Python config
   ✓ CORRECT: .env, .gitignore, config.py
   ✗ WRONG: env.txt, git.ignore, settings.ini

5. CONFIGURATION MODULES:
   - Use descriptive environment names
   - lowercase .py files
   - Examples: development.py, production.py, testing.py
   ✓ CORRECT: development.py
   ✗ WRONG: Development.py, dev.py
